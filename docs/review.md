# 코드 재검수 결과

2026-10-15 기준으로 발견한 오류를 수정하고 배포 파일을 갱신했다.

| 발견한 문제 | 수정 |
| --- | --- |
| 휴대폰 메타데이터만 남아 있으면 실제 JPEG가 없어도 Pi에 저장 완료 응답 | JPEG 존재/해시 확인, 누락·손상된 사진 재전송 복구 |
| 서버 응답 지연이 새 사진의 휴대폰 파일 저장까지 지연 | 사진 저장과 네트워크 업로드 작업 큐 분리 |
| 손상된 메타데이터 또는 한 이벤트의 서버 거절이 뒤의 업로드까지 중단 | 손상 파일 보존 후 건너뛰기, 409/413/422 개별 처리 |
| 비ASCII 인증 문자열을 비교할 때 서버 오류 | UTF-8 바이트 비교, README 토큰 예제 수정 |
| 완료 패킷 재전송 후 유휴 상태를 전송 중단으로 판단해 재연결 | 완료 이벤트는 수신 진행 시간 제한에서 제외 |
| SQLite 연결이 명시적으로 닫히지 않음 | 요청 처리 후 연결 종료 |

검증: Python/API/전송 테스트 20개 통과, 실제 Android 에뮬레이터 회귀 검사 6개 통과,
`assembleDebug`, `assembleDebugAndroidTest`, `lintDebug` 성공. 회귀 검사 중 앱 크래시는 없었다.

실제 Raspberry Pi BlueZ, 카메라, 휴대폰 BLE/GPS는 현장 테스트가 필요하다.
현재 GPS는 휴대폰의 첫 패킷 수신 시점 기준이다. 연결이 끊긴 동안 오래 대기한 이벤트는
실제 감지 위치와 차이가 날 수 있으며, 시연은 연결과 GPS가 준비된 상태에서 진행한다.
이번 앱은 화면을 열어 둔 상태로 사용한다.

서버 설정은 `ServerConfig.java`의 `BASE_URL`, `API_TOKEN`에서 지정한다.
앱의 서버/토큰 입력란과 설정 저장 버튼은 제거했다. 서버 주소가 미정이므로 현재 값은 비어 있고,
사진 수신·보관은 가능하며 업로드는 대기한다. 주소를 지정한 뒤 다시 빌드해야 한다.
Android 회귀 검사에는 서버 설정용 입력란이 없는지도 포함한다.
